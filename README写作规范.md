# AXI 学习文档写作规范

## 1. 规范基准

本规范以 `ARM_IHI_0022H_AMBA_AXI_and_ACE_Protocol_Specification_A3.md` 的成稿形式为基准，用于后续 AXI 章节的整理、重写和配图。

文章面向具备基本数字电路知识、正在学习 AXI 的初学者。内容应能脱离原规范独立阅读，也应方便复制到微信公众号编辑器继续排版。

专业结论以适用版本的 Arm 规范为准。学习笔记、截图和旧文章只是素材，不能替代原文核对。发现版本差异、编码歧义或勘误风险时，应明确说明，不能自行补成确定规则。

## 2. 文件与目录

每章在项目根目录保存为：

```text
ARM_IHI_0022H_AMBA_AXI_and_ACE_Protocol_Specification_章节编号.md
```

配图放在 `image/axi-章节编号/`，每张正式图片同时保存可编辑 `.drawio` 和高清 PNG；生成、校验脚本放在 `tools/`。

原始学习笔记、旧图和风格参考图保留，不覆盖、不删除。正式文章只引用本次核对过的新图。章节完成后更新根 `README.md` 的索引，写清内容、配图数量、完成状态和仍需注意的版本问题。

## 3. 固定文章结构

文章按以下顺序组织：

1. 标题。
2. 开篇说明。
3. 学习目标。
4. 整体认识。
5. 按规范小节展开的正文。
6. 易错点。
7. 原文覆盖对照表。
8. 自测题。
9. 下一章衔接。
10. 参考来源和非官方说明。

### 3.1 标题与开篇

标题同时说明章节编号、核心主题和读者收获：

```text
# A3：AXI 单接口要求——从一次握手看懂完整读写与突发地址
```

开篇使用引用块给出四项信息：

```text
> 阅读对象：读者当前具备什么基础、希望解决什么问题。
> 依据：规范编号、章节名、原文页码。
> 范围：覆盖哪些小节，以哪个协议版本为主。
> 前置知识：阅读前需要掌握的概念；配图是否为教学重绘。
```

### 3.2 学习目标与正文

学习目标列出 3～6 个可检查的能力，使用“判断、计算、区分、解释、画出”等动作词，避免“了解”“熟悉”。

正文先建立整体认识，再进入细节。每个主题依次写：

1. 这个机制解决什么问题。
2. 先看图或具体案例。
3. 按采样点、数据拍或地址逐项解释。
4. 给出可以推广的协议结论。
5. 标明规范章节和页码依据。
6. 每条面向读者的可推广结论都必须有案例覆盖：结论前至少展开一个具体时序、数据、地址或边界案例，让读者能在案例中看到结论如何成立。若结论包含多个条件，案例必须覆盖这些条件；案例未出现或未解释的条件不能直接写进结论，应补案例、拆分结论或明确标注待核对。

原规范顺序不利于初学者理解时，可以调整讲解顺序，但原文覆盖对照表必须证明所有小节和重要说明都已覆盖。

### 3.3 易错点与覆盖表

易错点优先使用三列表格：

| 常见误解 | 正确理解与误解原因 | 回看位置 |
| --- | --- | --- |

每项说明为什么容易误解。时序、编码、版本差异以及“允许/必须”的混淆优先收录。

文章结尾必须逐页检查原文覆盖：

| PDF 章节或页码 | 原文知识点 | 本文位置 |
| --- | --- | --- |

正文、Note、Caution、表格、公式和原图表达的关键含义都要进入对照表。配图可以重新组织原图信息，但不能以图片代替正文解释。

### 3.4 自测题

每章提供 5～10 道题，每题只检查一个判断点，并使用独立折叠块：

```html
<details>
  <summary>1. 题目</summary>

  <span style="background-color:#FBC952;color:#4A3410;font-weight:700;">明确结论。</span>解释和规范依据。

</details>
```

优先使用波形判断、地址计算、合法性判断和常见误解，不把术语抄写当作主要考查方式。

## 4. 表达与术语

首次出现的术语采用“英文全称＋统一中文＋一句通俗解释”，例如：

```text
Backpressure（反压）指接收方用 READY 为低暂缓接收。
```

| 英文 | 统一中文 |
| --- | --- |
| Master | 主设备 |
| Slave | 从设备 |
| Interconnect | 互连 |
| Transaction | 事务 |
| Burst | 突发传输 |
| Beat | 数据拍 |
| Transfer | 传输 |
| Payload | 载荷 |
| Byte Lane | 字节通道 |
| Register Slice | 寄存器切片 |

新版规范使用 Manager、Subordinate 等名称时，应说明它们与本文用语的对应关系。

必须区分“规范规定”“规范推荐”“允许/可以”“本例选择”和“教学算法/类比”。示例延迟不能写成协议固定性能，协议许可不能写成实现义务。

明确、可直接记忆的结论使用：

```html
<span style="background-color:#FBC952;color:#4A3410;font-weight:700;">结论文字。</span>
```

一处只高亮一个核心判断。过程说明和规范依据保持普通正文。

正文还应满足：

- 一段只讲一个中心意思，先给判断，再解释原因。
- 信号、字段、数值和地址使用行内代码。
- 并列条件使用编号列表，每项只表达一个判断。
- 比较编码、版本和案例时使用 2～4 列表格。
- 公式、伪代码和可执行示例使用代码块，前后解释用途和边界。
- 不使用手敲字符波形、字符框图或字符箭头流程图。
- 正文不放网页链接、站内跳转或“点击这里”。

## 5. 时序图统一模板

视觉参考保存在 `image/axi-a3/timing-style-reference.png`。它只规定版式和配色，不是协议时序依据。

### 5.1 视觉样式

1. 白色背景、黑色波形、醒目黑色标题，信号名在左侧对齐。
2. 顶部用 `T1、T2…` 标记采样点，每点配竖向虚线和上升沿箭头。
3. 等待沿使用淡橙色竖条，成功握手使用淡绿色竖条。
4. 复位有效区用淡蓝底色；复位释放后的区域可用淡绿底色，并标明阶段。
5. 蓝色说明一般条件，橙色说明等待，绿色说明成功传输。
6. 图下依次放关键事件说明框、核心协议结论和本例假设。
7. 输出宽度使用 1440 像素；标题、信号名和说明文字不小于 32 像素。

### 5.2 时序语义

图例统一写明：

```text
时间向右；虚线为采样上升沿；按边沿前取值判断，信号在沿后更新。
```

每张时序图必须满足：

1. 只有同一采样沿 `VALID=1 && READY=1` 才标成该通道成功传输。
2. 等待期间 VALID 和完整载荷保持，包括地址、数据、LAST、RESP、WSTRB 及适用的侧带信号。
3. 连续传输按成功握手的采样沿计数，不能按 VALID、数据或 LAST 保持的周期数计数。
4. 波形延伸到完整事务结束：读至少画到带 RLAST 的末拍握手，写至少画到 B 握手。
5. 图下写明主从双方驱动的信号，以及省略字段的固定取值或图外行为。
6. 示例处理延迟、READY 初值和空闲电平注明为本例选择。
7. 每次复用模板都重新核对信号值、拍数、依赖和复位时机，不能照抄参考图波形。

复杂场景应拆图。例如 AW 先到、W 先到和两者同拍分别绘制，不缩小字号硬塞进一张图。

## 6. 结构图与数据图

结构图与时序图使用同一字体和主色：主设备及请求方向用蓝色，从设备用绿色，响应方向用紫色。

地址、突发、WSTRB 和非对齐访问优先使用教学表格图：表头淡蓝，正文白色与浅灰蓝隔行，底部绿色框列出本例条件和结论。地址统一使用十六进制，并明确 AxSIZE 指编码还是解码后的字节数。字节通道应按 lane、数据位段和内存地址交叉核对。

图后紧跟图注：

```text
图 1：图片说明（教学重绘）
```

图中已有的逐拍数值不在正文整表重抄；正文解释读图方法、关键边界和可推广结论。

## 7. 技术核对清单

### 7.1 握手与依赖

- 按采样沿前的值判断握手。
- VALID 不能依赖对应 READY；READY 可以等待 VALID，但接口输入输出间不能形成组合路径。
- AXI4/AXI5 的 BVALID 必须在对应地址握手和带 WLAST 的末拍数据握手之后产生。
- 读数据必须在对应 AR 握手后返回；RVALID 不能等待 RREADY。
- LAST 必须随最后数据拍成功握手，不能单独作为事务完成条件。

### 7.2 地址与数据

- 拍数按 `AxLEN + 1`，每拍最大字节数按 `2 ** AxSIZE` 计算。
- 区分 AXI3、AXI4 的长度限制以及 INCR、FIXED、WRAP 的不同限制。
- 非对齐 INCR 第一拍从起点开始，第二拍回到按 AxSIZE 对齐后的递增地址。
- WRAP 起点按每拍大小对齐，长度只能为 2、4、8 或 16，并按完整容器计算边界。
- 4KB 检查覆盖最后一个可能访问的字节，不能只比较首末拍地址。
- WSTRB 只能选择当前地址和大小允许的写字节通道；读通道没有 WSTRB 或 RSTRB。
- 错误响应不能提前取消剩余数据拍。

### 7.3 版本与歧义

同一版本出现编码与解码量混用、不同 AXI 版本规则不同、后续版本更名或定义修订、实现行为无法从本地规范确认时，必须增加“版本文字核对说明”。列出原文写法、冲突点和本文处理方式；不能隐藏问题，也不能凭经验替规范改错。

## 8. 生成与验证

每章完成前检查：

1. 原始学习笔记的哈希或内容没有变化。
2. 正式 Markdown 只引用本次确认的新图。
3. 每个 PNG 都有同名 `.drawio`，源文件能正常打开。
4. 图片无裁切、重叠、乱码，缩放到约 540 像素宽仍可读。
5. 脚本复算各通道成功握手沿、等待保持、LAST 和响应依赖。
6. 独立复算 FIXED、INCR、WRAP、非对齐和 4KB 边界案例。
7. Markdown 只有一个一级标题，代码围栏成对，图片路径存在。
8. `<details>` 标签成对，每题包含题目、明确答案和依据。
9. 正文没有字符拼接图，也没有外部网页链接。
10. 原文覆盖对照表逐页核对，没有用摘要掩盖遗漏。
11. 逐条回查可推广结论、高亮结论和易错点，确认每条都能回指到至少一个已展开案例；没有案例支撑的结论不得仅靠抽象总结保留。

A3 当前使用 `tools/draw_a3_v2.py` 生成图片，由 `tools/verify_a3_v2.py` 检查文档、配图、握手和地址案例。后续章节沿用相同的生成和验证思路。

## 9. 发布与完成标准

发布前确认标题、开篇信息、术语解释、结论强度、图文顺序、手机可读性、易错点、自测题、覆盖表和纯文本来源。公众号编辑器不支持 `<details>` 时，只在发布稿展开答案，不修改仓库原稿。

一篇章节只有同时满足以下条件才标记完成：

1. 对照适用版本规范逐页核对，没有遗漏正文、重要说明、表格、公式和原图含义。
2. 初学者不打开其他页面也能理解文章主线和示例。
3. 所有正式图片准确、清晰，并有可编辑源文件和正文解释。
4. 时序、地址、字节范围、响应和自测答案经过独立复算。
5. 版本差异和无法消除的原文歧义已显式标注。
6. 根目录文档索引已更新，原始资料仍完整保留。

参考样稿：Arm IHI 0022H《AMBA AXI and ACE Protocol Specification》A3 中文学习导读。

## AXI README 写作规范

后续 A1、A2、A3 等 AXI 学习文档统一遵守以下规则：

1. 按规范原有章节组织内容，信号名、字段名和协议术语保留英文，解释使用通俗中文。
2. 一段只表达一个主要观点。同一处包含多个并列结论、条件或时序判断时，拆成 `1、2、3、4` 编号列表，每条只讲一个结论。
3. 讲解时序时，先给图，再按时钟采样点逐条说明发生了什么；逐拍说明之后，再单独列出可以推广的协议结论。
4. 每条时序结论写清信号条件和结果，例如在 `ACLK` 上升沿同时满足 `VALID=1`、`READY=1`，该通道才完成一次传输。
5. 时序图使用本机 draw.io 绘制。仓库同时保存可编辑的 `.drawio` 源文件和导出的高清 PNG，并按 `image/axi-章节编号/` 分目录存放；已有 A1 图片不强制迁移。
6. 图中必须标明采样点、关键信号、有效数据和等待区间，并延伸到足以展示完整事务，不能用截断波形支撑拍数、等待或完成条件等结论。
7. 观点后给出规范章节或页码依据。多个结论共用依据时，把依据单独放在列表末尾，避免塞进某一条结论。
8. 面向微信公众号的正文不放超链接。规范名称、版本、章节和页码使用纯文字注明；仓库根 README 可以保留内部导航链接。
9. 不逐句翻译或大段复制规范原文，使用自己的语言解释信号分工、判断方法和常见误解。
10. 带有明确判断、规则或可直接记忆的结论性文字统一使用 `<span style="background-color:#FBC952;color:#4A3410;font-weight:700;">结论</span>` 标成 `#FBC952` 黄色底、深棕色字并加粗。过程介绍、图前说明和规范出处保持正文样式，让黄色标记只承担突出结论的作用。
11. 时间方向、采样点、颜色、数据占位符和等待区间等读图说明直接放进 draw.io 图例。波形已经清晰表达高低电平时，不再额外堆叠 `0/1`；编码或缩写应在图中就近说明含义，例如 `4'b1111`、`INCR` 和 AXI4 的 `AWLOCK=0`。正文只解释图中事件和协议结论，不重复图例。
12. 每篇章节末尾设置“自测题”章节。题目按一个题目一个判断点编写，覆盖本章核心信号和时序。每道题直接作为默认收起的 `<details>` 摘要，点击题目后展开答案，不显示“查看答案”等额外字样；答案结论使用统一的 `#FBC952` 黄色底、深棕色字并加粗。
13. `<details>` 折叠块保持清晰层级：`<summary>` 和答案内容相对 `<details>` 缩进两格，摘要后和闭合标签前保留空行。
14. 时序讲解统一采用“先看图、再逐拍解释、最后总结通用规则”的顺序。传输次数按 `ACLK` 上升沿同时满足 `VALID=1`、`READY=1` 的次数计算，不能按数据或 `LAST` 保持的周期数计算。
15. 每条可推广结论都必须有具体案例覆盖；结论涉及的每个条件都要在案例中出现并解释，不能只凭抽象总结下结论。案例不足时补案例、拆分结论或标注待核对。
